# Сайт брокера

## Назначение

Публичная витрина брокера: рассказывает о продукте и ведёт клиента к регистрации. Отдельный
продукт со своим образом и контейнером (ADR-017), общего кода с [[web-ui]] нет. Каталог
`apps/site/`, наружу порт **8889**.

## Запуск

```bash
docker compose up --build site    # → http://localhost:8889
```

## Состав

- `public/index.html` — лендинг: шапка, первый экран, рынки, возможности, шаги, призыв, подвал.
- `public/style.css` — строгая тема на CSS-токенах; светлая тема не дублирует правила,
  а переопределяет токены под `:root[data-theme="light"]`.
- `public/i18n.js` — словарь EN/RU, разметка помечена `data-i18n`. Язык в `localStorage`.
- `public/theme.js` — тема: выбор пользователя → системная настройка → тёмная.
- `public/markets.js` — виджет таблицы рынков по контракту [[ADR-015-reusable-frontend-modules]]
  (`Markets.mount(el, ctx)`, свои стили, `filter()` для поиска).
- `public/auth.js` — окна входа и регистрации (`Auth.mount(el, ctx)`): валидация, индикатор
  надёжности пароля, показ/скрытие, согласие с условиями. Доступность: `role="dialog"`,
  фокус заперт внутри и возвращается на кнопку-открывашку, Esc и клик по фону закрывают.
- `public/site.js` — композитор: шапка (поиск, язык, тема, бургер) + виджет рынков + окна auth.

## Данные

Котировки живые — nginx сайта проксирует `GET /instruments` на [[gateway]]. Цены форматируются
по `price_decimals` из ответа, хардкода нет. Лента первого экрана и таблица рынков берут один
источник.

## Содержание страницы

Цифры на сайте — **только реальные** (живые котировки). Придуманных показателей вроде числа
клиентов, объёмов торгов, наград или лицензий на странице нет и быть не должно: на сайте брокера
это вводит в заблуждение. Явно указано, что среда демонстрационная и торговля бумажная.

## Вход и регистрация

Формы полностью рабочие как интерфейс: проверка почты, требования к паролю (8+ символов, буква и
цифра), совпадение паролей, обязательное согласие с условиями и раскрытием рисков, индикатор
надёжности.

**Отправка намеренно не подключена.** Настоящей системы аккаунтов ещё нет, а вешать публичную форму
на dev-эндпоинт `/admin/users` нельзя: он без пароля и без какой-либо защиты — это открытая
регистрация для кого угодно. Отправка инъектируется через `ctx.submit`, поэтому подключение
настоящего auth — правка в одном месте (`site.js`).

## Ограничения / TODO

- **Настоящий auth**: пароли (хэш+соль), сессии, подтверждение почты, восстановление пароля,
  ограничение частоты попыток. До этого форма показывает, что регистрация закрыта.
- Личный кабинет клиента — отдельный продукт, `apps/cabinet/`.
- Разделы Futures / Earn / Square пока указывают на существующие секции лендинга: страниц под них нет.
- Ссылка на терминал вычисляется как `hostname:8888` — при выкладке за один домен заменить на
  нормальный путь/поддомен.
- Нет SEO-разметки (Open Graph, sitemap) и аналитики.
