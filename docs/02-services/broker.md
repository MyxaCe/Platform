# Broker (бумажный)

## Назначение

Исполнение сделок в broker-режиме на **бумажных деньгах** и **реальных ценах** (ADR-014):
открыл BUY/SELL позицию по рынку → P&L двигается по реальной цене → закрыл, зафиксировал прибыль/
убыток. Реальных денег нет, депозиты виртуальные. Крейт `broker/` (чистая логика, зависит от `domain`).

## Модель

- Деньги — в **центах** (`i128`). Счёт: стартовый баланс задаётся gateway из
  `DEMO_START_BALANCE_CENTS` (compose: $10k; дефолт в коде, если переменной нет, — $100k).
- Позиция: `{ instrument, side: Long|Short, qty(raw), entry(raw), pd, qd, margin }`.
- `value = price_raw · qty_raw · 100 / 10^(pd+qd)` (центы). PnL Long = `value(mark−entry)`, Short = `value(entry−mark)`.
- Открытие: маржа = нотионал / leverage (пока **leverage=1**); нужно `free = balance − used_margin ≥ margin`.
- Закрытие: `balance += realized_pnl`. Equity = `balance + Σ нереализованный PnL`.

## Две модели ведения позиций (ADR-025, реализовано 2026-09-04)

Счёт работает по одной из двух моделей. Модель — свойство **счёта**, не позиции:
неттинг это отношение между позициями, и на отдельной позиции он не имеет смысла.

| | Хеджирование (`hedging`) | Неттинг (`netting`) |
|---|---|---|
| Встречная сделка | открывает вторую, независимую позицию | сворачивает существующую |
| Доливка в ту же сторону | вторая позиция | одна позиция, вход усредняется по объёму |
| Позиций на инструмент | сколько угодно | не больше одной |
| Выход лимитным ордером | **невозможен** | обычная операция |

**Маржа при доливке проверяется только на добавку**, а не на полный объём позиции.
Часть маржи уже занята этой же позицией: требовать её повторно значило бы отказывать
в доливке при достаточных средствах. Записано явно, потому что выглядит небрежностью,
пока не объяснено, и первый же рефакторинг «для строгости» это ломает.

**Частичное сворачивание.** Встречный объём меньше открытого — позиция уменьшается,
вход не меняется (свёрнута часть, а не заключена новая сделка), маржа пересчитывается
на остаток, в историю попадает свёрнутая часть с фактическим объёмом. Встречный объём
больше — позиция закрывается, остаток открывает позицию в новую сторону; в историю
идёт только закрытая часть, остаток ещё не закрыт.

**Смена модели** (вариант A по ADR-025): новая модель тенанта применяется к счёту
только когда у него **нет открытых позиций**. Пока позиции есть, счёт продолжает
работать по прежней — это не отказ, а отложенный переход: каждый счёт мигрирует в
свой ближайший «плоский» момент. Отложенные ордера переходу не мешают: они ещё не
позиции и риска не несут.

Счета, заведённые до 2026-09-04, поднимаются как `hedging` — другой модели в коде не
существовало, это факт их истории, а не умолчание.

Модель отдаётся в `GET /account` полем `model` и показывается в шапке терминала:
она меняет смысл каждой встречной сделки, и человек обязан видеть её до того, как не
сойдётся баланс.

**Чего ещё нет:** выбор модели из конфига тенанта (`GET /v1/sites/{slug}`) — ждёт
ключа к CMS вместе с allow-list и стартовым балансом. Сейчас модель меняется только
программно. Там же появится счётчик немигрировавших счетов в `/health`.

## Как было до ADR-025: модель хеджирующая (TRM-08, найдено 2026-09-03)

Каждое открытие заводит **новую независимую позицию**. Встречная сделка по тому же
инструменту существующую позицию **не закрывает и не уменьшает** — она открывает
вторую, противоположную. Закрыть позицию можно только явно: `close(user, id, mark)`
по её `id`, либо срабатыванием её собственных SL/TP.

Практическое следствие, о котором пользователь не предупреждён: **лимитным ордером
нельзя выйти из позиции.** Держа Long и поставив лимитную продажу «на выход», человек
при срабатывании получит вторую позицию (Short), а первая останется открытой. Маржа
займётся дважды, а сделка, которую он считал закрытой, продолжит жить.

Решение принято 2026-09-04: поддержать **обе** модели, выбор — per-tenant из конфига
брокера ([[ADR-025-position-model-netting-vs-hedging]], статус `accepted`; открыт
вопрос о судьбе позиций, открытых до смены модели). До реализации действует описанное
ниже.

Это выбор торговой модели — **хеджирующая** (как MT5 hedging) против неттинговой, — и
сделан он молча, кодом (`Account::try_open` вызывается и из `open`, и из триггера
отложенного ордера; неттинга нет ни там, ни там). Решение, оставлять ли так, за
владельцем: варианты — неттинг, явная пометка в интерфейсе или сознательное
подтверждение текущей модели. До ответа поведение зафиксировано здесь, чтобы
перестать быть неявным.

Для allow-list инструментов (ADR-023 Т3) это свойство удобно: раз лимитный ордер
всегда вход, а не выход, границу на нём ставить правильно — см. `06-operations`.

## Публичный API

- `Broker::new(start_balance, leverage)`
- `open(user, instrument, side, qty, entry, pd, qd, sl, tp) -> Result<pos_id>` — позиция с опц. SL/TP
- `close(user, id, mark) -> Result<Cents>` (реализованный P&L, пишет в историю)
- `place_pending(...) -> id` / `cancel_pending(user, id)` — лимитные (отложенные) ордера
- `check(marks)` — триггеры лимитных ордеров и SL/TP по текущим ценам (вызывает фоновый монитор gateway)
- Чтение: `balance/used_margin/free_margin/positions/pendings/closed_deals/open_pnl/equity`
- `enum BrokerError { InsufficientMargin, UnknownPosition, UnknownPending }`

Лимитный buy срабатывает при `mark ≤ price`, sell — при `mark ≥ price`. SL/TP закрывают позицию при
достижении уровня. Закрытые сделки пишутся в историю (`ClosedDeal`).

## Связи

- Используется [[gateway]]: эндпоинты `POST /deals`, `GET /deals`, `POST /deals/{id}/close`, `GET /account`.
- Цены входа/марк — из реального фида ([[gateway]] `feed`): buy=ask, sell=bid, марк=last.
- Основано на [[ADR-014-paper-broker]].
