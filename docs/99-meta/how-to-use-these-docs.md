# Как ведём документацию

Цель: чтобы **и ты, и ассистент** могли за секунды найти нужный модуль, понять его
устройство и связи, а также историю решений и багов.

## Структура папок

```
docs/
├── README.md                 ← Home / карта (открывается первой)
├── 00-principles/            ← принципы разработки, стандарты
├── 01-architecture/          ← общая архитектура
│   └── decisions/            ← ADR (Architecture Decision Records)
├── 02-services/              ← по одному файлу на сервис/модуль
├── 04-bugs/                  ← журнал багов
├── 05-improvements/          ← backlog идей и улучшений
└── 99-meta/                  ← мета: как вести доки
```

## Правила

- **Wiki-ссылки.** Связываем заметки через `[[имя-файла-без-расширения]]`. Obsidian строит граф —
  так видно связи между модулями.
- **Уникальные имена файлов.** Имя файла = якорь ссылки, поэтому имена уникальны в пределах vault.
- **Frontmatter.** Вверху каждого файла YAML-блок: `tags`, `status`, `updated`. Помогает фильтрам
  и поиску Obsidian.
- **Один модуль — один doc.** Для каждого сервиса/модуля своя заметка в `02-services/` со стандартным
  скелетом (см. ниже).
- **Решения — только через ADR.** Не переписываем историю: устаревшее решение помечаем `superseded`
  и ссылаемся на заменяющий ADR.
- **Синхронность.** Документация меняется вместе с кодом, в одном изменении.

## Скелет doc'а сервиса/модуля

```markdown
---
tags: [service]
status: draft | active
updated: YYYY-MM-DD
---
# <Название модуля>
## Назначение         — зачем существует, одна-две фразы
## Публичный API       — функции/типы с сигнатурами и кратким описанием
## Входящие команды/события
## Исходящие события
## Связи               — [[другие-модули]], кто вызывает, кого вызывает
## Инварианты          — что всегда должно быть истинно
## Ограничения / TODO
```

## Быстрый поиск неисправного модуля

1. Открой [[services-index]] → найди подозреваемый модуль.
2. В его doc'е — раздел «Связи»: пройди по `[[ссылкам]]` вверх/вниз по потоку.
3. Проверь [[bug-log]] — не встречался ли похожий симптом.
