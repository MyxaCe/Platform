# ADR-007 — Структура крейтов: общий `domain`

## Статус

`accepted`.

## Контекст

Появился второй потребитель доменных типов (`Price`, `Qty`, `AssetId`, …) — Ledger. Держать эти
типы внутри matching-крейта `exchange-core` означало бы, что Ledger зависит от matching-ядра — это
неверное направление зависимости (Ledger не должен тянуть матчинг).

## Решение

Выделить общий словарь в отдельный крейт **`domain`** (без логики, только типы и реестр
инструментов). От него зависят:

```
        ┌──────────┐
        │  domain  │  Price, Qty, Amount, Side, OrderId, OrderType,
        └────┬─────┘  TimeInForce, AssetId, InstrumentId, Instrument,
             │        InstrumentRegistry, UserId
      ┌──────┴───────┐
      ▼              ▼
┌───────────┐   ┌──────────┐
│   core    │   │  ledger  │   (не зависят друг от друга)
│ (matching)│   │ (деньги) │
└───────────┘   └──────────┘
```

Workspace: `members = ["domain", "core", "ledger"]`. `exchange-core` re-export'ит доменные типы
для удобства (тесты/адаптеры не ломаются).

## Последствия

- `core` больше не содержит `src/domain/` — типы переехали в крейт `domain`.
- Дешёвый рефактор сейчас (2 потребителя) вместо дорогого позже. Прямое следствие принципа
  «модульные границы = будущие границы сервисов».
- `command`/`event` остаются в `core` (они специфичны для матчинга).
