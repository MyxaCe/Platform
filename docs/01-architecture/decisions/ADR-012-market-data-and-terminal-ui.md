# ADR-012 — Market data (свечи), несколько пар и терминальный UI

## Статус

`accepted`.

## Контекст

Нужен профессиональный терминал (в стиле референс-скрина): список инструментов слева, свечной
график с таймфреймами, панель BUY/SELL. Для этого нужны серверные данные: несколько пар, свечи с
историей, живые цены по всем инструментам.

## Решение

- **Крейт `marketdata`** — агрегация сделок в свечи (OHLCV) по таймфреймам (`CandleStore`).
  Чистая логика без async/зависимостей; тесты быстрые. Границевый сервис (время — снаружи).
- **Gateway** ведёт `CandleStore`: на каждую сделку `ingest(instrument, ts, price, qty)` (ts —
  серверные секунды, боундари). Эндпоинты:
  - `GET /instruments` — список с `last/change/bid/ask/high/decimals`;
  - `GET /candles/{id}?tf=SEC&limit=N` — свечи таймфрейма.
- **Несколько пар** в демо-сиде (BTC/ETH/SOL/XRP/DOGE к USDT), у каждой свои `price_decimals`.
- **Демо-симулятор рынка** — фоновая tokio-задача: по каждой паре двигает mid, обновляет котировки
  (cancel+repost maker bid/ask) и делает встречную рыночную сделку (два sim-пользователя, без
  self-trade). Наполняет стакан, ленту и свечи, чтобы всё жило само. Плюс синтетический бэкфилл
  истории свечей при старте (чтобы график не был пустым).
- **UI-редизайн** (терминал): верхняя панель метрик (BALANCE/EQUITY/…), левый список инструментов
  (INSTR/CHANGE/SELL/BUY/SPREAD/HIGH), тулбар таймфреймов, график с OHLC, правая панель BUY/SELL с
  лотом, нижние вкладки. Свечи теперь серверные (`/candles`), live-обновление через WS.

## Последствия

- Симулятор и бэкфилл — **демо-данные** (явно помечены), не реальные котировки; ledger двигают
  только настоящие сделки sim-пользователей. Для прод-режима симулятор выключается.
- Свечи в памяти (не персистентны) — durable-журнал будет в Фазе 3. [[backlog]]
- Суммы/цены масштабируются на клиенте по `decimals` из `/instruments` (хардкода больше нет).
