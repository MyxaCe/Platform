# ADR-003 — Событийность и детерминизм ядра

## Статус

`accepted`.

## Контекст

Бирже нужны: аудит (кто, что, когда), воспроизводимость (восстановить состояние на любой момент),
согласованность между балансами, стаканом и историей. Классический CRUD-подход (изменяем строки в
БД) этого не даёт: нельзя переиграть, тяжело аудировать, легко рассинхронить проекции.

## Решение

**Event sourcing + детерминированное ядро.**

1. Внешний мир шлёт ядру **команды** (`PlaceOrder`, `CancelOrder`, …).
2. Ядро — чистая функция: `apply(state, command) -> { state', events[] }`. Оно **не** трогает время,
   случайность, сеть, диск. Всё недетерминированное (текущее время, сгенерированные id) передаётся
   **внутрь команды** снаружи.
3. Ядро порождает **события** (`OrderAccepted`, `Trade`, `OrderCanceled`, …) — неизменяемый
   упорядоченный журнал. Журнал — единственный источник истины.
4. Всё остальное — **проекции** журнала: балансы (ledger), стакан, свечи, история сделок, лента в UI.

```
Команда ──► [ Ядро: pure apply() ] ──► События ──► Журнал (истина)
                                                      │
                        ┌─────────────┬───────────────┼─────────────┐
                     Ledger       Order Book       Свечи        История/WS
                   (проекция)     (проекция)     (проекция)     (проекция)
```

## Последствия

- **Плюсы:** воспроизводимость (replay журнала → то же состояние), аудит, согласованность проекций,
  простое тестирование (golden/replay-тесты), лёгкий распил на сервисы (Фаза 3) — проекции просто
  подписываются на журнал.
- **Минусы/плата:** дисциплина — недетерминированные входы обязаны инжектиться снаружи; схемы событий
  версионируются (событие в журнале живёт вечно, ломать формат нельзя — только добавлять новые версии);
  чуть больше кода, чем «UPDATE в таблице».
- **Следствия для кода:** запрет `Date.now()`/`Math.random()` в ядре (принцип №2 в [[development-principles]]);
  каждое событие и команда — с уникальным id (идемпотентность); события неизменяемы.
- Опирается на целочисленную арифметику из [[ADR-002-money-representation]] (иначе replay не
  детерминирован).
