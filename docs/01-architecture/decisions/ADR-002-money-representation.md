# ADR-002 — Представление денег, цен и объёмов

## Статус

`accepted`.

## Контекст

Биржа считает деньги. Ошибка округления = реальные потери и несходящийся баланс.
Числа с плавающей точкой **непригодны**: `0.1 + 0.2 != 0.3`. Нужна точная целочисленная арифметика.

## Решение

**Целые числа в минимальных единицах, как Rust-newtypes.** Для каждого инструмента задаются:
- `price_decimals` — знаков в цене (масштаб = `10^price_decimals`);
- `qty_decimals` — знаков в объёме;
- `tick_size`, `lot_size` — шаг цены и объёма (в тех же целых единицах).

Доменные типы — **newtypes поверх `i64`**, чтобы нельзя было случайно сложить цену с объёмом:

```rust
pub struct Price(pub i64);  // цена в минимальных единицах
pub struct Qty(pub i64);    // объём в минимальных единицах (lot units)
```

- Внутри ядра — только целочисленная арифметика над этими типами.
- Нотионал (`price * qty`) считается в `i128`, чтобы исключить переполнение.
- Конвертация в человекочитаемый вид (строки с точкой) — **только на границе** (API/UI), не в ядре.

## Последствия

- Нужны хелперы `scale`/`unscale` и форматирование на адаптерах-границах.
- Арифметика денег — через методы доменных типов, а не голые операторы где попало.
- Инвариант: сумма балансов по каждому активу сходится к константе (проверяется в рантайме, Фаза 2).
- Целые числа → детерминированный replay журнала ([[ADR-003-event-sourcing-and-determinism]]).
