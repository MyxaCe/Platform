# ADR-020 — Passkey / WebAuthn

> **Superseded [[ADR-022-standalone-terminal-pivot]] (2026-07-25):** снят вместе со слоем входа.

## Статус

`accepted` (2026-07-22). Первый из «быстрых входов», не требующий внешних ключей — нужен только
HTTPS (есть, ADR-019).

## Контекст

Вход был по паролю (ADR-018). Passkey даёт беспарольный вход по биометрии/PIN устройства: приватный
ключ не покидает устройство, сервер хранит только публичный и проверяет подпись. В отличие от
Google/Apple/Telegram/MAX, здесь не нужны ключи провайдера и подтверждение домена в чужой консоли.

## Решение

**`webauthn-rs`** для серверной проверки церемоний. Модуль `gateway/src/passkey.rs`, ключи хранятся
в БД (таблица `passkeys`: публичный ключ + id учётных данных), приватный ключ — только на устройстве.

- **RP ID = `meriom.com`** (регистрируемый домен), поэтому ключ действует на всех поддоменах
  (accounts/trade/my). Origin и id — из окружения (`WEBAUTHN_RP_ID`, `WEBAUTHN_ORIGIN`).
- **Регистрация** (`/auth/passkey/register/*`) — под сессией: залогиненный пользователь привязывает
  ключ. UI — в кабинете, раздел «Безопасность».
- **Вход** (`/auth/passkey/login/*`) — после ввода почты: сервер отдаёт список ключей пользователя
  (`allowCredentials`), браузер выбирает подходящий, сервер проверяет подпись и открывает сессию.
- Состояние церемонии (challenge) живёт на сервере, привязано к одноразовому `flow`-id (5 минут) —
  подменить его на клиенте нельзя.

### Почему вход после ввода почты, а не discoverable

Хотелось кнопки «войти по ключу» на первом экране (discoverable — браузер сам предлагает ключи).
Не вышло: `webauthn-rs` при регистрации по умолчанию создаёт **не-discoverable** ключи
(`residentKey: discouraged`), а попытка форсировать resident на клиенте ломает `create()` —
конфликтует с расширением `credProtect`, которое ставит библиотека (`NotSupportedError: protection
policy inconsistent`). Бороться с внутренностями библиотеки ради этого не стали.

Вход после почты (`allowCredentials`) — надёжный и распространённый вариант (так делают GitHub,
многие банки). Компромисс приемлемый: почта на входе и так вводится. Discoverable-кнопка на первом
экране — возможное улучшение, когда/если перейдём на resident-ключи ([[backlog]]).

### Стоимость: OpenSSL в сборке

`webauthn-rs` линкуется с системной OpenSSL (крипта COSE). В `rust:slim` её нет, поэтому в
`gateway/Dockerfile`, `scripts/test.sh` и CI добавлены `libssl-dev`/`pkg-config` (сборка) и `libssl3`
в рантайм-образ. Раньше проект был на чистом rustls; это первая нативная зависимость.

## Последствия

- **Плюсы:** беспарольный вход без внешних провайдеров и без затрат; ключ работает на всех
  поддоменах; фишинг-устойчив (ключ привязан к домену). Задаёт основу — общий фронт-модуль
  `shared/passkey.js` переиспользуют accounts (вход) и cabinet (привязка).
- **Минусы/плата:** нативная зависимость OpenSSL в образах; не discoverable (нужен ввод почты);
  подтверждение почты и список ключей пользователя пока не показываются в UI (только «добавить»).
- **Проверка:** end-to-end через виртуальный WebAuthn-аутентификатор Playwright (CDP
  `WebAuthn.addVirtualAuthenticator`) — регистрация ключа → выход → вход по ключу → та же учётка.
  Плюс серверные тесты граничных случаев (нет сессии → 401, нет ключа → 404).
- **Осталось:** несколько ключей и их отзыв в UI, «умный» баннер conditional-UI, перенос
  `verified`/passkey-метаданных профиля в БД полностью. [[backlog]]
