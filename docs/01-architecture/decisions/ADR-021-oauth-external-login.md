# ADR-021 — Вход через внешних провайдеров (OAuth 2.0)

## Статус

`accepted` (2026-07-22). Первый провайдер — **Яндекс**; Google, Telegram, MAX и др. встают тем же
скелетом по мере появления ключей.

## Контекст

Кроме почты+пароля (ADR-018) и Passkey (ADR-020), нужны быстрые входы через внешних провайдеров.
У всех OAuth-провайдеров одинаковая механика, поэтому делаем один провайдер-независимый скелет, а
каждый провайдер — это строка конфига.

## Решение

Модуль `gateway/src/oauth.rs`. Поток на примере Яндекса:

1. `GET /auth/oauth/:provider/start` — ставит cookie `oauth_state` (случайный, защита от CSRF) и
   303-редиректит на страницу авторизации провайдера с `client_id`, `redirect_uri`, `scope`, `state`.
2. Провайдер возвращает пользователя на `/auth/oauth/:provider/callback?code&state`.
3. Сверяем `state` из query с cookie; меняем `code` на `access_token` (server-to-server);
   запрашиваем userinfo, берём **подтверждённую провайдером почту**.
4. По почте находим или создаём пользователя, помечаем почту подтверждённой, открываем **свою**
   сессию (та же cookie, что у остальных входов) и редиректим в кабинет `my.<домен>`.

Провайдер описывается таблицей (`authorize`/`token`/`userinfo`/`scope`/поле почты/схема токена);
`client_id` и `client_secret` — **только из окружения**, в коде и git их нет. Отдельный провайдер
«включён», только если его ключи заданы.

### Решения по деталям

- **Redirect URI строится из заголовка `Host`** (`https://accounts.<домен>/auth/oauth/<p>/callback`) —
  совпадает с зарегистрированным у провайдера и не требует отдельной переменной. Схема всегда https
  (мы за HTTPS-edge).
- **UI показывает только настроенные кнопки.** Фронт спрашивает `GET /auth/oauth/providers` и
  включает лишь вернувшиеся; ненастроенные (Google/Apple/…) остаются неактивными. Кнопка, ведущая в
  никуда, читается как поломка — этого избегаем.
- **OAuth-аккаунт создаётся без пароля** (пустой хэш): войти паролем нельзя, пока пользователь его
  не задаст. Аккаунты связываются по почте — если она уже есть, OAuth просто логинит.
- **CSRF-state в cookie** с `Path=/auth/oauth`, `HttpOnly`, `SameSite=Lax` (пропускает cookie на
  верхнеуровневом редиректе-возврате), живёт 10 минут.
- **Любой сбой ведёт на страницу входа** с `?error=oauth`, а не показывает сырую ошибку.

## Последствия

- **Плюсы:** быстрый вход без пароля; один скелет — новый провайдер добавляется парой строк конфига
  и ключами в `.env`; почта от провайдера уже подтверждена, шаг с кодом не нужен.
- **Минусы/плата:** аккаунт без пароля, пока не задан (нужна будущая «установка пароля» / сброс);
  связывание по почте предполагает, что провайдер её подтверждает (Яндекс/Google — да);
  `verified` пока в памяти (общий техдолг из ADR-019).
- **Проверено:** `/start` 303-редиректит на Яндекс с верным `redirect_uri`/`state`; `/providers`
  отдаёт `["yandex"]` (Google без ключей исключён); кривой `state` и неизвестный провайдер → отбой на
  вход; кнопка Yandex активна, остальные — нет. Реальный вход в аккаунт Яндекса проверяет владелец в
  браузере (интерактивный шаг).
