# ADR-013 — Реальные данные и разворот к брокер-терминалу

## Статус

`accepted`.

## Контекст

Симулированные цены не нужны — нужны реальные. TradingView использовать нельзя (нет публичного API,
парсинг запрещён ToS). Реалтайм по форекс/сырью/акциям/индексам — платный/лицензируемый; крипта —
бесплатна (публичный Binance). Владелец выбрал: **модель брокер-терминала** (реальные цены из фида,
сделки BUY/SELL по рыночной цене; наш matching-движок уходит в фон), **начать с крипты**.

## Решение

- **Убираем симулятор** и синтетические свечи полностью.
- **Источник крипто-данных — Binance** (публичный, без ключа), топ-30 пар:
  - **Свечи/история**: REST `api/v3/klines` по запросу `/candles`, кэш ~2с (реальный OHLCV).
  - **Живые цены/лента**: WebSocket combined stream `@ticker` (last/change/high/bid/ask для
    `/instruments`) + `@aggTrade` (реальные сделки → лента и live-обновление свечи через `/stream`).
- **Масштаб**: у каждой пары свои `price_decimals`/`qty_decimals` (таблица); строки Binance
  парсятся в целые raw-единицы.
- **Не-крипто рынки** (форекс major/minor/exotic, сырьё, акции EU/US/РФ, индексы) — **в backlog**:
  требуют платного дата-провайдера и API-ключа (реалтайм лицензируется), РФ осложнена санкциями.
- **Исполнение сделок** (broker-режим: позиции/маржа/P&L, фикс по рыночной цене) — **следующий этап**.
  Matching-ядро/ledger/оркестратор сохраняются как фундамент, но UI-терминал их пока не исполняет.

## Последствия

- Gateway получает внешние зависимости: `reqwest` (REST), `tokio-tungstenite` (WS).
- Данные реальные и совпадают с рынком (ETHUSDT ≈ TradingView). Больше никакой симуляции.
- Зависимость от доступности Binance (в некоторых регионах 451; на dev-машине доступен).
- Тесты матчинга/ledger не затронуты (фид — отдельный слой, сеть только в `main`, не в тестах).
