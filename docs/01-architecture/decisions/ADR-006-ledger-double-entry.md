# ADR-006 — Ledger: счета, балансы и двойная запись

## Статус

`accepted`.

## Контекст

Ledger хранит деньги пользователей. Требования: баланс **всегда** сходится (ничего не создаётся
и не исчезает, кроме явных депозитов/выводов), средства под заявку резервируются заранее, при
исполнении корректно переходят контрагенту, при отмене — возвращаются.

## Модель

- **Счёт** = `(UserId, AssetId)`. У каждого счёта баланс `Balance { available, held }`.
  `available` — свободно; `held` — зарезервировано под активные заявки.
- **Двойная запись**: каждая операция балансова — сумма изменений по активу равна нулю
  (кроме депозита/вывода). Инвариант: `total_supply(asset)` постоянна между депозитами/выводами.
- **Суммы** — целочисленный newtype `Amount(i128)` (шире `i64`, т.к. нотионал = цена×объём).

## Операции

- `deposit` / `withdraw` — внешнее пополнение/вывод (меняют total_supply).
- `reserve` — `available → held` (при постановке заявки; ошибка `InsufficientAvailable`).
- `release` — `held → available` (при отмене/остатке).
- `settle_fill` — расчёт сделки (атомарно, балансово).

### Расчёт сделки (`settle_fill`)

Сделка по инструменту `(base, quote)`, цена `P`, объём `q`, между покупателем и продавцом.
Покупатель резервировал `quote` по своей лимитной цене `L` (для лимитной заявки), исполнение —
по цене maker'а `P ≤ L`, поэтому разница `(L−P)·q` возвращается покупателю (price improvement):

```
Покупатель:  held[quote]      −= L·q
             available[quote] += (L−P)·q      (возврат разницы)
             available[base]  += q
Продавец:    held[base]       −= q
             available[quote] += P·q
```

Проверка сходимости:
- `quote`: `−L·q + (L−P)·q + P·q = 0` ✓
- `base`:  `+q − q = 0` ✓

Продавец резервирует `base` (объём) — резерв точный, возврата не требует.

## Последствия

- Ledger — отдельный крейт `ledger/` (см. [[ADR-007-workspace-crate-structure]]); зависит от `domain`,
  но **не** от matching-ядра.
- Резерв под **рыночную** заявку (цена заранее неизвестна) — отдельная задача; в первом срезе
  `settle_fill` принимает `buyer_reserve_price` явно, а связывание резерва с заявкой — на оркестраторе
  (Фаза 2b). См. [[backlog]].
- Инвариант сходимости проверяется тестами (`total_supply` до/после серии операций).
