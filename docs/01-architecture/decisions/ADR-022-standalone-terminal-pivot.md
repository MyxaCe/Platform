# ADR-022 — Пивот на автономный встраиваемый терминал

## Статус

`accepted` (2026-07-25). Замещает продуктовую рамку ADR-017/018/019 и снимает с живого пути
ADR-006/008/009/010(частично)/020/021. Сам терминал (ADR-013/014) и его инфраструктура
(ADR-015/016) сохраняются как ядро.

## Контекст

Проект разросся в четыре продукта — сайт брокера, вход/аккаунты, кабинет, терминал — со своей
аутентификацией, поддоменами, HTTPS и edge-маршрутизацией. Владелец переосмыслил продукт:

> «Это теперь просто терминал, который будет использоваться для множества других сайтов.»

Терминал становится **самодостаточным встраиваемым продуктом**. Сайт платформы и CMS будут
отдельными сущностями и определяются позже; как именно внешний сайт/CMS авторизует своего
пользователя в терминале — **отложенное решение** (см. «Последствия»).

Держать под это ядро биржи-стакана (matching), двойную бухгалтерию, аутентификацию и
мультипродуктовый repo-layout — значит тащить мёртвый вес: на живом пути терминала ничего из
этого не использовалось (реальные цены Binance + бумажный брокер, ADR-013/014).

## Решение

**Терминал автономный, без логина, на одном счёте по умолчанию** (`DEFAULT_USER = UserId(1)`).
Всё, что не относится к пути «данные + бумажная торговля», удалено.

Снесено:

- **Крейты** `core` (matching-движок), `ledger` (двойная запись), `orchestrator`, `marketdata`,
  `auth` (крипта паролей/сессий/Passkey).
- **Модули gateway** `authn.rs`, `oauth.rs`, `passkey.rs`, `mailer.rs`; хендлеры и DTO матчинга
  (`/orders`, `/book`, `/balance`, `EventDto`, `publish`), funding (`/account/deposit|withdraw`),
  admin (`/admin/*`) и весь слой аутентификации (`/auth/*`).
- **Продукты** `apps/{site,accounts,cabinet,shared,edge}` — сайт, вход, кабинет, общие модули,
  edge-прокси.
- **Инфраструктура входа**: поддомены, mkcert-HTTPS, cookie `Domain=.meriom.com`, OAuth/Passkey
  env, сертификаты. Домен `meriom.com` больше не участвует.

Осталось (ядро терминала):

- Крейты `domain` (типы денег/инструментов, деньги целыми), `broker` (бумажный брокер: позиции,
  маржа=1, P&L, SL/TP, лимитные ордера), `persistence` (счета в PostgreSQL за трейтом
  `Persistence`), `gateway` (axum: `feed.rs` — данные Binance + REST/WS терминала).
- Роуты: `/health`, `/instruments`, `/candles/:i`, `/depth/:i`, `/stats/:i`,
  `/deals` (POST+GET), `/deals/closed`, `/deals/:id/close`, `/pending` (POST+GET),
  `/pending/:id` (DELETE), `/account` (GET), `/stream` (WS).
- Дисциплина персистентности `with_account` (ADR-016) сохранена без изменений.

**Развёртывание**: `docker compose` = `postgres + gateway + terminal`. Терминал (nginx) отдаёт
статику и проксирует API/WS на gateway; наружу торчит только он на **:8888**. Edge не нужен —
терминал самодостаточен. HTTP, без TLS (терминал встраивается в чужой сайт, TLS — на стороне
хоста/фронта интеграции).

**Хранилище**: таблицы `users/sessions/passkeys/credentials` удалены; счёт (`accounts`,
`positions`, `pendings`, `closed_deals`) хранится сам по себе — `user_id` больше не ссылается на
`users`.

## Последствия

- **Один счёт, деньги демо.** Реальных денег по-прежнему нет; красная линия №1 (деньги целыми)
  и №5 (инварианты в рантайме) сохранены.
- **Интеграция с внешними сайтами/CMS — открытый вопрос.** Как пользователь внешнего сайта
  получает свой счёт (передача личности, изоляция счетов, авторизация встраивания) — отдельное
  будущее решение. Пока `DEFAULT_USER` — единственная личность.
- **Восстановимость.** Всё удалённое остаётся в истории git (ветка `master`) — при возврате
  matching-ядра/аутентификации код поднимается из прошлых коммитов.
- **Замещения.** ADR-017 (repo-layout из 4 продуктов), ADR-018 (аутентификация), ADR-019
  (поддомены и ступенчатый вход) — **superseded**. ADR-020 (Passkey), ADR-021 (OAuth) —
  **superseded** вместе со слоем входа. ADR-006 (ledger), ADR-008 (orchestrator), ADR-009
  (market-orders/STP), ADR-010 (gateway-стек в части matching-DTO) — код снят, ADR помечены как
  вышедшие из живого пути (matching может вернуться отдельным продуктом-биржей).
