# ADR-001 — Язык и стек ядра

## Статус

`accepted` — **Rust** для ядра (matching engine + ledger).

## Контекст

Ядро должно быть корректным, детерминированным, тестируемым и с предсказуемой латентностью.
Событийная архитектура ([[ADR-003-event-sourcing-and-determinism]]) позволяет позже вынести/масштабировать
части, не переписывая всё.

## Рассматриваемые варианты

- **TypeScript (Node.js)** — быстрый старт, но GC-паузы и позже неизбежный переезд горячего ядра.
- **Go** — быстрый, простой, но менее строгая доменная типизация.
- **Rust** ✅ — максимум производительности и безопасности без GC; строгие типы (newtypes для денег),
  исчерпывающий pattern matching (идеален для команд/событий), детерминизм. Так пишут топовые биржи.

## Решение

**Rust (edition 2021).** Причины: детерминизм и отсутствие GC-пауз критичны для matching engine;
система типов даёт бесплатную защиту доменных инвариантов (newtypes `Price`/`Qty`, `enum` для команд
и событий с проверкой полноты веток). Строим сразу «правильно», без переписывания ядра позже.

Плата, которую принимаем осознанно: выше порог входа и медленнее старт, чем на TypeScript.

## Последствия

- **Cargo workspace** в корне репозитория; крейт ядра — `core/` (`exchange_core`).
- **Фаза 1 — только `std`, без внешних зависимостей** (детерминизм + быстрая сборка в Docker).
- Тулчейн — **через Docker-образ `rust`** (локально Rust не установлен). См. [[ADR-004-docker-rust-toolchain]].
- Деньги — целочисленные newtypes (`i64`), см. [[ADR-002-money-representation]].
- Фронтенд/адаптеры (позже) остаются на TypeScript/web — Rust только там, где нужна корректность и скорость.
