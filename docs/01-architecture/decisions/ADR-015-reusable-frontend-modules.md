# ADR-015 — Переиспользуемые фронтенд-модули (mount + ctx)

## Статус

`accepted`.

## Контекст

Фронтенд терминала вырос в один монолит `web/public/app.js` (~460 строк, 53 КБ), намертво сшитый с
`index.html`: ~94 обращения к `document.getElementById` по конкретным id страницы и общее изменяемое
глобальное состояние (`selected`, `META`, `tf`, `rawCandles`…), которое функции читают/пишут напрямую.
Единственный по-настоящему отдельный модуль — `drawings.js`, и тот тянет глобал `window.__lw` и
хардкодит id.

Следствие: ни один кусок (стакан, статистика, панель сделки, watchlist) нельзя переиспользовать на
другой странице или в тесте, не утащив за собой пол-`app.js`. Владелец продукта принял решение:
**переписать модули на переиспользование, и все новые модули делать такими же.**

## Решение

**Каждый фронтенд-модуль — самодостаточный, зависимости инъектируются, глобалы и id страницы под
запретом.**

Контракт модуля-виджета:

```js
const handle = Widget.mount(rootEl, ctx);   // rootEl — точка монтирования; ctx — зависимости
// handle: { refresh(), destroy(), ... }     // маленький явный API наружу
```

- Модуль **сам строит свой DOM** внутри `rootEl` (страница даёт только пустой контейнер).
- Всё внешнее — через `ctx`: текущее состояние как **колбэки** (`ctx.instrument()`), данные как
  **инъекция источника** (`ctx.fetch(id)`), реакции как **колбэки** (`ctx.onPick(price)`). Модуль
  не знает про `fetch('/depth')`, `selected` или id соседних элементов.
- Модуль **не читает/не пишет чужие глобалы** и не хардкодит id страницы.
- Чистая логика (без DOM и состояния) выносится в **отдельный модуль-библиотеку** с экспортом-объектом.

Первый заход (этот ADR):

- **`indicators.js`** — вся математика индикаторов (~35 чистых функций), `window.Indicators`. Ноль DOM,
  ноль глобалов. `app.js` берёт их деструктуризацией. Пригодно для UI, бэктеста, тестов.
- **`orderbook.js`** (`OrderBook.mount`) и **`stats.js`** (`AssetStats.mount`) — виджеты стакана и
  статистики по паттерну `mount(root, ctx)`, задают образец для остальных.

Второй заход (2026-07-19):

- **`api.js`** — `Api.create({ token })`, модуль-библиотека. Заголовок авторизации и разбор ответов
  были продублированы в восьми местах `app.js`, а токен читался прямо из элемента страницы — то есть
  любой виджет, которому нужен сервер, привязывался к разметке. Настоящий auth (P0 в [[backlog]])
  поменяет заголовки и добавит обработку `401`; с этим модулем правка будет в одном месте.
- **`watchlist.js`** — `Watchlist.mount(root, ctx)`: список инструментов со всем своим хозяйством
  (поиск, сортировка, избранное, колонки). Первый виджет, который **строит свой DOM целиком** —
  `index.html` отдаёт пустой `<aside class="watch">`. Цены форматирует сам по `price_decimals` из
  данных, поэтому внешний форматтер в `ctx` не понадобился.

Порядок подключения: `lightweight-charts` → `api.js` → `indicators.js` → `orderbook.js` →
`stats.js` → `watchlist.js` → `app.js` → `drawings.js`.

Замечание по порядку монтирования: виджет, чей `ctx.onSelect` дёргает соседей, монтируется
последним. `watchlist` при первом обновлении выбирает инструмент, а обработчик выбора обращается к
`book`/`stats` — они должны быть созданы раньше.

Осталось вынести: панель сделки, нижние вкладки, клиент-фид (WS + интервалы), лейаут/настройки,
график и `drawings.js` (он контракту пока не соответствует).

## Стили едут вместе с модулем (2026-07-20)

Аудит показал главный пробел: JS был развязан, а **представление — нет**. Классы (`.brow`,
`.stat__v`, `.irow`) описывались в общем `style.css`, плюс виджеты зависели от токенов темы из
`:root` там же → перенесённый виджет отрисовывался голыми `div`-ами. Закрыто:

- **Каждый виджет возит свою CSS внутри модуля** и инжектит её в `<head>` один раз при загрузке
  (guard по `id` стиля). Страница-хост может не иметь ни строчки своей CSS.
- **Токены темы — контракт хоста, но с фолбэками:** `var(--down,#ef5350)`. Есть тема — виджет
  вписывается в неё; нет — рисует себя дефолтными цветами. Тема остаётся сквозной, а виджет
  перестаёт от неё зависеть.
- **Размещение остаётся за хостом.** Компонент отвечает за свой внутренний вид, но не решает, где
  ему стоять: `.deal__book` (как стакан вписан в правую панель) остался в `style.css`.
- **`mount()` делает первичную отрисовку сам.** Раньше виджет рисовался только по `refresh()` из
  `app.js` — на чужой странице он молчал. Это нарушало обещание «ставится одной строкой».

**`drawings.js` приведён к контракту:** `Drawings.mount(root, cfg)`, сам создаёт свой canvas и панель
инструментов внутри `root`, график и серию получает через `cfg` (глобал `window.__lw` удалён),
глобальное событие `chartReload` заменено явным `draw.clear()`. Внутри зависимости названы `cfg`,
т.к. `ctx` занято под 2D-контекст канвы.

### Статус модулей

| Модуль | Контракт | Стили в модуле | Вердикт |
|---|---|---|---|
| `indicators.js` | чистые функции, DOM нет | н/д | ✅ |
| `api.js` | токен через `ctx.token()` | н/д | ✅ |
| `orderbook.js` | `mount(root, ctx)` | ✅ | ✅ |
| `stats.js` | `mount(root, ctx)` | ✅ | ✅ |
| `watchlist.js` | `mount(root, ctx)` + `storagePrefix` | ✅ | ✅ |
| `drawings.js` | `mount(root, cfg)` | ✅ | ✅ |
| `positions.js` | `mount(root, ctx)` | ✅ | ✅ |

Проверено headless: 19 замеров вычисленных стилей до/после переноса совпали до символа; затем на
странице с **удалёнными всеми `<link rel=stylesheet>`** виджеты смонтированы одной строкой и
отрисовались полностью (цвета — из фолбэков).

Открытый вопрос: селекторы не изолированы (`.irow`, `.brow` — глобальные имена). На чужой странице
возможна коллизия классов. Пока не мешает; при появлении коллизий — скоупить под класс корня.

**Нижняя панель вынесена (2026-07-20):** `positions.js` — вкладки OPEN DEALS / LIMIT ORDERS /
CLOSED DEALS / SIGNALS со своим DOM, стилями, опросом и делегированием кликов по кнопкам строк.
Два решения по границе: позиции виджет отдаёт хосту колбэком `onDeals` (график сам рисует линии
SL/TP — виджет в график не лезет), а **сигналы приходят снаружи** через `ctx.signals()`, потому что
считаются из свечей, которыми владеет хост: виджет отвечает за показ, но не за расчёт.

Остаётся в `app.js`: панель сделки, клиент-фид (WS + интервалы), лейаут/настройки, график.

Технически — без бандлера (проект отдаёт статику через nginx): модуль = IIFE, экспорт в один
неймспейс на `window`. Появится сборка — те же модули переезжают в ES-модули без смены контракта.

## Последствия

- **Плюсы:** модули ставятся на любую страницу одной строкой; тестируются в изоляции; `app.js` худеет
  и превращается в тонкий «композитор» (связывает виджеты через `ctx`); граница `ctx` — единственная
  точка связи, менять реализацию можно не трогая страницу. Согласуется с принципом «модульные границы =
  будущие границы» ([[development-principles]] №10–11).
- **Минусы/плата:** немного больше церемоний (описать `ctx` вместо прямого доступа к глобалу); пока нет
  бандлера — дисциплина «один неймспейс на `window`, подключать в правильном порядке».
- **Обязательность:** распространяется на **все новые модули**; старые (watchlist, панель сделки,
  график, клиент-фид, лейаут) переносятся постепенно по этому же паттерну. Зафиксировано принципом №11.
- **Не событийность и не Фаза 3:** это про переиспользование UI-кода, ортогонально event sourcing ядра
  ([[ADR-003-event-sourcing-and-determinism]]).
