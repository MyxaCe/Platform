# Журнал багов

Каждый нетривиальный баг фиксируется здесь. Формат записи:

```markdown
## BUG-XXX — краткий заголовок
- **Дата:**
- **Модуль:** [[имя-модуля]]
- **Симптом:** что наблюдали
- **Причина (root cause):** почему на самом деле сломалось
- **Фикс:** что изменили (ссылка на коммит)
- **Регресс-тест:** какой тест теперь ловит это
- **Статус:** open | fixed
```

## BUG-001 — Зум графика сбрасывается каждые несколько секунд
- **Дата:** 2026-07-17
- **Модуль:** [[web-ui]]
- **Симптом:** приблизишь график — через ~4с он откатывается на весь диапазон.
- **Причина:** периодическое обновление (каждые 4с) делало `setData` всех свечей + `fitContent()`,
  затирая пользовательский вид.
- **Фикс:** `setData`/установка вида — только при смене инструмента/ТФ; live-обновление
  формирующейся свечи через `series.update()`; сверка с сервером (`syncLast`) тоже через `update()`.
- **Регресс-тест:** ручной (в `app.js` нет `fitContent` в периодических путях; `grep -c fitContent = 0`).
- **Статус:** fixed

## BUG-002 — Цены на графике не те (ETH ~1800 вместо ~3400)
- **Дата:** 2026-07-17
- **Модуль:** [[gateway]] (`gen_history`), [[web-ui]]
- **Симптом:** список слева показывал верную цену (~3396), а график — совсем другую (~1800).
- **Причина:** синтетическая история свечей была неограниченным случайным блужданием — уходила
  далеко от базовой цены; плюс была оторвана от live-симулятора (он стартовал с base, история
  заканчивалась в другом месте) → разрыв и «чужой» масштаб на исторической части графика.
- **Фикс:** `gen_history` — блуждание с возвратом к среднему и границами ±20% от base; симулятор
  стартует mid с последней исторической цены (`last_price`) → непрерывность history↔live.
- **Регресс-тест:** ручной (разброс close истории ETH держится в ±20% base; последняя ист. свеча
  ≈ live `last`).
- **Статус:** fixed

## BUG-003 — «Дневной» таймфрейм показывает недели/месяцы
- **Дата:** 2026-07-17
- **Модуль:** [[web-ui]]
- **Симптом:** на 1D видно слишком длинный период; зум не держится.
- **Причина:** следствие BUG-001 — `fitContent()` откатывал на все 240 свечей (для 1D ≈ 8 мес.),
  и на старте подгонялась вся история.
- **Фикс:** при загрузке показываем последние ~90 баров (`setVisibleLogicalRange`), вид не трогается
  при обновлениях.
- **Статус:** fixed

## BUG-004 — Новый REST-эндпоинт отдаёт 405/SPA вместо API (повторяющийся)
- **Дата:** 2026-07-17
- **Модуль:** [[web-ui]] (`apps/terminal/nginx.conf`)
- **Симптом:** новый путь (напр. `/deals`, `/account`, `/instruments`, `/candles`) на POST даёт 405,
  на GET отдаёт HTML SPA вместо ответа gateway.
- **Причина:** nginx проксирует API по регекс-списку `^/(orders|book|...)`; новый путь туда не добавлен →
  попадает в статику. Повторяется при каждом новом эндпоинте.
- **Фикс:** добавить путь в регекс `location ~ ^/(...)` в `apps/terminal/nginx.conf` и пересобрать web.
- **Профилактика:** предупреждение в [[gateway]] рядом с таблицей эндпоинтов.
- **Статус:** fixed (для /deals,/account)

## BUG-006 — Время на оси графика не совпадает со временем в легенде (open)
- **Дата:** 2026-07-17
- **Модуль:** [[web-ui]] (`app.js` — `fmtDT` / легенда)
- **Симптом:** время внизу графика (ось) ≠ время в инфо-карточке слева вверху для той же свечи.
- **Причина (диагностировано):** легенда форматирует время свечи через `new Date(t*1000).toLocaleString('ru-RU', ...)`
  — это **локальная таймзона** пользователя. А ось времени lightweight-charts по умолчанию показывает
  время в **UTC**. Отсюда сдвиг на величину смещения таймзоны.
- **Фикс (план, завтра):** привести к одной зоне — либо форматировать легенду в UTC (`timeZone: 'UTC'`),
  либо настроить график на локальную зону (`localization` / `tickMarkFormatter`). Выбрать одну зону
  консистентно (вероятно UTC, как биржевой стандарт).
- **Статус:** open (в очереди на 2026-07-18)

## BUG-005 — Пустая страница: не видно ни монет, ни графика
- **Дата:** 2026-07-17
- **Модуль:** [[web-ui]] (`app.js`)
- **Симптом:** после добавления индикаторов страница полностью пустая (нет списка пар, нет графика).
- **Причина:** в реестре `OVERLAYS` использовано сокращение `supertrend`, а функция названа `superTrend`
  (заглавная T) → `ReferenceError: supertrend is not defined` при вычислении объект-литерала на верхнем
  уровне → весь `app.js` падает до первичной отрисовки (файл единый).
- **Диагностика:** headless Playwright → `pageerror: supertrend is not defined`, coins 0.
- **Фикс:** `supertrend: superTrend`. Плюс `Cache-Control: no-cache` в nginx (чтобы браузер не подсовывал
  старый app.js).
- **Профилактика:** проверять рендер headless-браузером после крупных правок фронта.
- **Статус:** fixed
## BUG-007 — Статика `stats.js` уходила в API-прокси → 404
- **Дата:** 2026-07-19
- **Модуль:** [[web-ui]] (`apps/terminal/nginx.conf`)
- **Симптом:** при выносе виджетов в модули (ADR-015) `indicators.js` и `orderbook.js` отдавались 200,
  а `/stats.js` → **404**. Страница осталась бы без виджета статистики.
- **Причина:** регекс API-прокси `^/(orders|book|...|stats|...)` не имел границы пути и матчил **префикс**.
  Путь `/stats.js` подходит под `^/stats` → запрос уходил в gateway, где такого маршрута нет (есть
  `/stats/{id}`) → 404. Родня BUG-004: тот же регекс, но обратная сторона — раньше API не попадал в
  прокси, теперь в прокси попала статика.
- **Фикс:** добавлена граница пути — `^/(orders|book|...|health)(/|$)`. API (`/stats/2`, `/orders`,
  `/account`) по-прежнему проксируется, статика с тем же префиксом (`/stats.js`) — нет.
- **Проверено:** статика `indicators/orderbook/stats.js` → 200; API `/stats/2`, `/depth/1`,
  `/instruments` → 200.
- **Профилактика:** имена новых статических файлов не должны совпадать с префиксами API — а лучше
  (сделано) граница `(/|$)` в регексе, чтобы коллизия была невозможна в принципе.
- **Статус:** fixed

## BUG-008 — График сыпал `RangeError` в консоль, подписи оси зависели от локали ОС
- **Дата:** 2026-07-19
- **Модуль:** [[web-ui]] (`app.js` — `createChart`)
- **Симптом:** при headless-проверке после выноса `watchlist.js` консоль дала 10 ошибок
  `pageerror: Incorrect locale information provided`. В обычном браузере разработчика ошибка не
  проявлялась — поэтому жила незамеченной.
- **Причина:** `createChart` вызывался без опции `localization`, и lightweight-charts форматировал
  подписи оси времени через `Date.toLocaleString(navigator.language)`. В окружении без настроенной
  локали (headless-контейнер) `navigator.language` пустой → `RangeError` в `formatTickmark`.
  Ошибка не только косметическая: у клиента с любой другой локалью ОС формат дат на оси уезжал бы,
  хотя весь интерфейс проекта английский.
- **Диагностика:** Playwright, `pageerror` со стеком → `lightweight-charts.js … Gn.formatTickmark`.
- **Фикс:** `localization: { locale: 'en-US' }` в `createChart` — формат дат перестал зависеть от
  машины клиента.
- **Регресс-тест:** headless-прогон проверяет «консоль без ошибок» (принцип №20).
- **Статус:** fixed

## BUG-009 — Колонки списка инструментов налезали друг на друга, тикер схлопывался в 0px
- **Дата:** 2026-07-19
- **Модуль:** [[web-ui]] (`watchlist.js`, `style.css`)
- **Симптом:** в списке инструментов тикеры обрезаны до неузнаваемости (`SOL/t`, `LINK/`, `XR`),
  числа соседних колонок сливались в кашу, шапка не совпадала со строками.
- **Причина:** треки грида задавались голыми `fr` (`1.55fr .82fr …`). У `Nfr` минимальный размер
  равен `min-content`, поэтому длинные цены (`0.00000413`) распирали числовые колонки, а колонка
  тикера сжималась до **0px** — при этом её текст продолжал рисоваться поверх соседей. Замер:
  `head: 18px 52.19 40.17 …` против `row: 18px 0px 40.78 …` — шапка и строка расходились.
- **Фикс:** треки обёрнуты в `minmax(0, …)` (разрешает сжатие ниже min-content) + `overflow:hidden;
  text-overflow:ellipsis` на ячейках, чтобы содержимое не выходило за свой трек.
- **Регресс-тест:** headless-скрипт сверяет `gridTemplateColumns` шапки и строки — они обязаны совпадать.
- **Остаток:** при ширине панели по умолчанию (280px) шести колонкам всё равно тесно, теперь цены
  режутся многоточием. Это вопрос дефолтной ширины/набора колонок — вынесен владельцу, см. [[backlog]].
- **Статус:** fixed (налезание устранено), читаемость при узкой панели — открытый вопрос

## BUG-010 — Тулбар графика вылезал поверх панели метрик; кнопка price type была некликабельна
- **Дата:** 2026-07-19
- **Модуль:** [[web-ui]] (`style.css` — `.toolbar`, `.tfs`, `.drawtools`; `app.js` — `applyLayout`)
- **Симптом:** обнаружено при расширении левой панели (следствие BUG-009). Кнопки таймфреймов
  наезжали на верхнюю панель метрик (`15M`, `30M` оказывались рядом с CREDIT). Замер показал, что
  дефект был **всегда**, просто малозаметен: группа ТФ выходила за тулбар на 10px при ширине панели
  280px, на 40px при 360px, на 100px при 440px. Дополнительно: панель инструментов рисования
  накрывала кнопку price type — `elementFromPoint` в центре `#ptBtn` возвращал `.drawtools`,
  то есть кнопка **не нажималась вообще**.
- **Причина:** три связанных дефекта верстки.
  1. `.toolbar` имел фиксированную `height` (и `applyLayout` дублировал её инлайном), при этом
     содержимое переносилось на новые строки. Расти вниз тулбар не мог, поэтому лишние строки
     выдавливались **вверх**, поверх шапки.
  2. Тулбар не помещается в одну строку на экране 1280px в принципе: одни только таймфреймы
     занимают 289px. При 280px было видно 5 кнопок из 8.
  3. `.drawtools` центрировалась через `top:50% + translateY(-50%)`. Панель выше своего
     контейнера, поэтому «центрирование» выносило её верх за пределы области графика — в тулбар.
- **Фикс:** `.toolbar` → `flex-wrap: wrap` + `min-height` вместо `height` (в CSS и в `applyLayout`)
  — тулбар переносит группы и растёт вниз, занимая две строки при узком центре; `.tfs` →
  `flex: 0 0 auto` + `nowrap`, чтобы группа ТФ переносилась целиком, а не рвалась посередине;
  `.drawtools` → прижата к верху (`top: 8px`) с `max-height: calc(100% - 16px)` и прокруткой.
- **Регресс-тест:** headless-скрипт проверяет `elementFromPoint` для всех восьми кнопок тулбара
  (все должны быть кликабельны) и видимость 8/8 таймфреймов при ширине панели от 280 до 460px.
- **Статус:** fixed

## BUG-011 — Отсутствие сессии выглядело как баланс $0 (класс дефекта)
- **Дата:** 2026-09-03
- **Модуль:** [[web-ui]] (`app.js` `pollAccount`, `api.js`, `positions.js`, `index.html`)
- **Симптом:** дефолтный `docker compose up` поднимал терминал с включённым SSO. Кабинета на
  машине нет → `/account`, `/deals`, `/pending` отдают `401 missing session`, а терминал
  показывал **BALANCE $0**, EQUITY $0, MARGIN $0 и пустые панели. Ни одной ошибки в консоли,
  ни одного признака отказа: график и стакан при этом живые, то есть интерфейс выглядел
  полностью исправным.
- **Причина:** `api.read()` по контракту возвращает `null` и на сетевую ошибку, и на не-2xx —
  «данных нет». `pollAccount` на `null` просто выходил (`if (!a) return`), оставляя в разметке
  стартовые значения `$0`, зашитые в `index.html`. То есть цифры на экране были не последним
  известным состоянием счёта, а **декоративной заглушкой**, неотличимой от настоящего нуля.
  Панели вели себя так же: `if (!list) return` оставлял пустой список, читаемый как «позиций нет».
- **Урок (класс, а не случай):** **отказ не должен выглядеть правдоподобным значением.** Ноль,
  пустой список, «0%», последняя известная цена — всё это валидные данные, по которым человек
  примет решение. Отказ, выглядящий как отказ, отправляет разбираться; отказ, выглядящий как
  данные, живёт месяцами. Правило вынесено штабом в `_brain/ПРАВИЛА.md` для всех команд.
- **Фикс:** `api.js` различает причину (`tradingStatus()`: `unknown` / `ok` / `no-session` /
  `unreachable`) — `null` больше не единственный сигнал. Стартовые значения метрик в разметке
  заменены на `—`: до первого успешного ответа цифр у нас нет. `pollAccount` при `no-session`
  ставит прочерки и показывает явное `NO CABINET SESSION — TRADING UNAVAILABLE`; при
  `unreachable` **оставляет прежние цифры** с пометкой `FIGURES MAY BE STALE` — сеть могла
  моргнуть, и затирать верные значения на каждый блип хуже. `positions.js` при `no-session`
  пишет в панелях причину вместо «No open positions».
- **Фикс (бэкенд, 2026-09-03, тот же класс — шесть мест):**
  1. `feed.rs::to_raw` возвращает `Option<i64>` вместо `unwrap_or(0.0)`: неразобранная строка —
     отказ, а не цена 0. Раньше нулевая цена уезжала в тикеры, свечи и стакан, и по ней
     считались бы P&L, маржа и триггеры SL/TP.
  2. `feed.rs::fetch_klines` — свеча с неразобранным полем роняет весь ответ, а не рисует
     свечу с нулевым low.
  3. `feed.rs::fetch_depth` — уровень с неразобранными числами пропускается, но пропуски
     считаются и логируются: молчаливый пропуск искажает стакан.
  4. `feed.rs::handle_msg` — котировка или сделка с неразобранным числом пропускается целиком
     с записью в лог (было: `unwrap_or("0")` в пяти полях тикера).
  5. `fetch_change` + `get_stats` — вместо `unwrap_or(0.0)` поле `change` стало `Option<f64>`:
     в JSON приходит `null`, фронт рисует `—`. «Не смогли посчитать» перестало выглядеть как
     «рынок стоял».
  6. `get_candles` / `get_depth` — при отказе отдают `503`, а не пустой массив; неизвестный
     инструмент — `404`, а не пустота. Пустой массив читается как «рынок пуст».
  Плюс потерянный класс ошибки: в цикле чтения WS `Ok(Message::Close(_)) | Err(_) => break`
  разделён на две ветки с логированием — обрыв фида был бесшумным, реконнект каждые 3 с
  выглядел как тишина. Диагностика, съеденная рабочим циклом, превращает отказ в задержку.
- **Фикс (UI рыночных данных):** отказ свечей больше не стирает график — прежние данные
  остаются, показывается бейдж `MARKET DATA UNAVAILABLE: <источники>`. Метрика **CREDIT**
  переведена в `—`: источника данных у неё нет вовсе, а нарисованный `$0` читался как
  «кредит равен нулю».
- **Регресс-тест:** headless-прогон в двух режимах: `SSO_DISABLED=1` — метрики показывают
  реальный баланс, предупреждения нет; SSO включён без кабинета — метрики `—`, предупреждение
  видно, «No open positions» не показывается. Автотеста нет: тестов фронтенда в проекте нет
  вовсе (TRM-05), поэтому проверка ручная и записана в [[06-operations]].
- **Регресс-тест (бэкенд, TRM-07, 2026-09-03):** дыру закрыли — было «проверено чтением
  кода», стало **22 теста на битый вход** в `feed.rs` (всего в проекте 55). Разбор вынесен
  в чистые функции (`klines_from_rows`, `depth_from_json`, `change_from_row`,
  `ticker_from_data`, `trade_from_data`, `parse_envelope`), и им подаётся мусор:
  отсутствующее поле, поле не того типа, `null`, обрезанное сообщение, `NaN`/`inf`,
  обрезанная строка свечи. Требование ко всем случаям одно: **битый вход не превращается
  в число** — только отказ или пропуск.
  **Мутационная проверка** (тест, не краснеющий от возвращённого дефекта, ничего не
  проверяет): в копию кода вернули три исходных дефекта — покраснели ровно ожидаемые тесты.
  `to_raw` → `unwrap_or(0.0)`: 7 красных; `change_from_row` → «0.00 % при отказе»: 2 красных;
  `parse_envelope` → молчаливый пустой конверт: 1 красный.
  Сверх тестов проверено **наблюдением на живом сервисе**: gateway поднят с
  `--add-host api.binance.com:127.0.0.1 --add-host stream.binance.com:127.0.0.1` — процесс
  жив, фид мёртв. `/candles` и `/depth` отдали `503` с записью причины в лог, `/stats` —
  восемь `null` вместо восьми нулей, `/health` — `feed_fresh:false`,
  `priced_instruments:0`. Способ поломки выбран по тому, что проверяем: ломается путь
  данных, а не процесс (`docker kill` проверил бы политику рестарта, а не фид).
- **Фикс (режим хранилища объявлен, КОНТРАКТЫ §5в):** обратное направление того же класса —
  `NoopStore` держал состояние в памяти, а интерфейс был неотличим от режима с БД, и после
  рестарта стартовый баланс выглядел настоящим счётом. Теперь режим объявляется **в двух
  местах**: полем в `/health` (`storage`, `durable`) — чтобы он был проверяем машиной, а не
  только глазами, — и постоянной пометкой в шапке `DEMO STATE — NOT SAVED BETWEEN RESTARTS`.
  **Пометка не закрывается**: закрытая пометка — та же тишина, только с согласия, о котором
  завтра не вспомнят. Проверено headless: с `durable:false` пометка видна и не содержит
  никакого элемента закрытия; с живым postgres скрыта.
- **Фикс (живость фида меряется данными, а не сокетом):** индикатор в шапке загорался на
  `ws.onopen`, то есть на соединении **браузер → gateway**. Если бы отвалился Binance, это
  соединение осталось бы целым, и зелёная точка утверждала бы живой рынок при молчащем фиде —
  здоровье процесса не означает наличия связи. Теперь точка горит по приходу данных
  (порог 20 с) и гаснет сама по таймеру, `/health` отдаёт `feed_fresh` и `feed_age_secs`,
  считая возраст **принятого** сообщения Binance, а не состояние сокета. Проверено ровно тем,
  что проверяется: `page.routeWebSocket` принимает соединение и молчит — точка гаснет,
  подсказка «no market data for …». Раньше в этом состоянии она была зелёной.
- **Фикс (подпись состояния):** рядом с названием биржи стояло статичное слово **LIVE** —
  утверждение о состоянии, нарисованное как украшение. Оно держалось бы и при мёртвом
  фиде. Теперь слово меняется вместе с индикатором (`LIVE` / `NO DATA`), а подсказка
  различает **транспорт** и **данные**: «no connection to terminal gateway» — сокет
  браузер→шлюз не поднялся; «socket open, no market data for Ns» — сокет цел, данных нет.
  Это разные неисправности, лечатся по-разному, и одинаково гасят точку. Проверено
  headless в трёх состояниях: живой фид, молчащий сокет, закрытый сокет.
  Тот же дефект нашёлся у соседей (кабинет и витрина зажигали «Данные в реальном времени»
  от `socket.on('connect')`), то есть он был общий для платформы, а не наш личный.
- **Статус:** fixed

## BUG-014 — Причина отказа handoff-токена не попадала никуда
- **Дата:** 2026-10-06
- **Модуль:** `gateway/src/sso.rs`
- **Симптом:** любой отказ валидации — не сошлась подпись, чужой `iss`, чужой `aud`,
  истёкший `exp`, отсутствующий claim — наружу отдавался одним `401 invalid token`, и
  **в лог не писалось ничего**. Снаружи один код правильно (различать для клиента, что
  именно не сошлось, значит подсказывать подбирающему), но изнутри разбирать живой отказ
  было нечем.
- **Причина:** `decode::<Claims>(...).map_err(|_| SsoError::BadToken)` — классический
  глушитель: `|_|` выбрасывает `ErrorKind`, в котором и лежала вся разница.
- **Чем вскрылось:** первым живым прогоном SSO (TRM-04). Пункт чеклиста «отказ при чужом
  `iss`/`aud`» проверяется только вживую, а проверить его было невозможно: подменённый
  payload падает на подписи, и снаружи это тот же `401`. То есть отсутствие диагностики
  не просто мешало — оно **блокировало единственный способ закрыть пункт контракта**.
- **Фикс:** причина пишется в лог фиксированной меткой (`reject_reason`), а не текстом
  ошибки библиотеки: текст может утащить в лог кусок разбираемого токена, метка не может.
  Ответ наружу не изменился.
- **Регресс-тест:** нет юнит-теста, и это осознанно. Проверка метки на самодельном токене
  проверяла бы наш токен, а не контракт. Пункт закрыт живым прогоном (см. ниже), метки
  наблюдались на настоящем токене кабинета.
- **Урок:** **диагностику проверяют тогда же, когда защиту.** Барьер работал, а узнать,
  что сработал именно он, было нельзя — и пункт контракта месяц числился «закрывается
  живым прогоном», хотя живой прогон его тоже не закрыл бы. Признак того же класса:
  `map_err(|_| ...)` на пути, по которому ходит проверка контракта.
- **Статус:** fixed

## BUG-013 — Тесты подмены `alg` не проверяли собственную защиту
- **Дата:** 2026-09-03
- **Модуль:** `gateway/src/sso.rs` (тесты)
- **Симптом:** написаны три теста на подмену алгоритма (`HS256`, `none`, `RS512`) — все
  зелёные. Мутационный прогон показал, что они остаются зелёными и **после удаления самой
  проверки** `header.alg != Algorithm::RS256`.
- **Причина:** отказ обеспечивается двумя слоями: нашей явной проверкой и `Validation::new(
  Algorithm::RS256)` внутри `jsonwebtoken`, которая тоже отвергает чужой алгоритм. Тесты
  проверяли **свойство** (токен отвергнут), а не **барьер** (отвергнут нами и до работы с
  ключами). Свойство при удалении барьера сохранялось библиотекой — и тесты молчали.
- **Урок:** зелёный тест на защиту не означает, что защита работает: он может держаться на
  другом слое. Отличить одно от другого умеет только мутация — снятие защиты. «Сделана,
  не заявлена».
- **Фикс:** добавлен `rejects_alg_before_touching_keys`: JWKS не посажен и недостижим,
  поэтому «дошли до ключей» видно по коду ошибки — `NoKeys` вместо `BadToken`. Барьер
  проверяется по наблюдаемому различию, а не по вере.
- **Регресс-тест:** он сам. Мутация «снять проверку alg» теперь красит ровно его.
- **Остаток:** явная проверка `alg` остаётся, хотя дублирует библиотеку — это защита от
  будущей правки `Validation`, и цена её нулевая.
- **Статус:** fixed
