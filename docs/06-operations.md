# Эксплуатация: репозиторий, CI/CD, запуск

## Продолжить работу на другой машине

```bash
git clone <адрес репозитория> platform
cd platform
cp .env.example .env          # при необходимости поправить
docker compose up --build -d  # первый запуск долгий: собирается Rust
```

Открывать: **https://meriom.com** (сайт), `accounts.` (вход), `trade.` (терминал), `my.` (кабинет).

Локально нужно:
1. **DNS** — A-записи `@` и `*` домена meriom.com на `127.0.0.1` (или строки в файле hosts).
2. **Локальный CA** — на каждой машине один раз:
   ```
   winget install FiloSottile.mkcert
   mkcert -install                       # добавляет CA в доверенные
   ```
   Сам сертификат (`apps/edge/certs/meriom.pem` + ключ) в git не хранится — сгенерировать:
   ```
   cd apps/edge/certs
   mkcert -cert-file meriom.pem -key-file meriom-key.pem meriom.com "*.meriom.com" localhost 127.0.0.1
   ```
   Без этого шага edge не поднимется (нет файлов сертификата), а браузер будет ругаться на HTTPS.

> Состояние (пользователи, счета, сделки) живёт в томе `pgdata` **на конкретной машине**.
> Между рабочей машиной и домом переносится код, а не данные: дома база будет своя, пустая.

## CI — `.github/workflows/ci.yml`

Запускается на каждый push и pull request:

| Задача | Что проверяет |
|---|---|
| `backend` | `cargo test --workspace` и `cargo clippy -- -D warnings` (предупреждение = ошибка) |
| `frontend` | `node --check` по всем модулям `apps/**` |
| `images` | `docker compose build` — ловит поломку Dockerfile до сервера |

`cargo fmt` пока в режиме `continue-on-error`: стиль по rustfmt не выравнивали, включить,
когда дойдут руки.

Проверка фронта не декоративная: единый `app.js` падает целиком от одной опечатки, и
страница остаётся белой — так было в BUG-005.

## CD — `.github/workflows/deploy.yml`

Запускается **вручную** (workflow_dispatch), не на каждый push: платформа работает с
деньгами клиентов, и выкладка должна быть решением человека, а не побочным эффектом коммита.

Чтобы включить, нужны:

1. Сервер с Docker и docker compose;
2. Секреты репозитория: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, опционально `DEPLOY_PATH`;
3. На сервере — клон репозитория и заполненный `.env`.

Пока секретов нет, workflow останавливается с понятным сообщением, а не падает молча.

## Настройки окружения

Все чувствительные значения — через `.env` (в git не попадает, шаблон в `.env.example`):

- `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` — **на сервере пароль обязательно сменить**,
  значения по умолчанию годятся только для разработки;
- `COOKIE_DOMAIN` — `.lvh.me` локально, `.вашдомен` на сервере;
- `COOKIE_SECURE` — включить, когда появится HTTPS;
- `SMTP_URL` / `MAIL_FROM` — пока не заданы, письма не отправляются, код подтверждения
  печатается в лог шлюза (ADR-019).

## Что ещё не сделано

- Нет автоматических UI-тестов в CI (headless-проверки гоняем руками, см. принцип №20).
- Нет сборки образов в реестр: сервер собирает сам, поэтому выкладка небыстрая.
- Нет бэкапов БД — обязательное условие до реальных денег. [[backlog]]
