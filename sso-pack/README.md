# SSO-пакет платформы · v1 (handoff-токены для терминала)

Контракт по решениям A/B финализации ([[Интеграция с терминалом]]). Модель: сессии платформы — opaque и отзываемые; терминалу выдаётся короткоживущий one-shot JWT; терминал чеканит СВОЮ сессию с TTL ≤ 15 минут и тихо продлевает её ре-handoff'ом.

## Эндпоинты платформы

| Эндпоинт | Кто зовёт | Что |
| --- | --- | --- |
| `GET {CABINET_URL}/api/sso/jwks` | терминал (кешировать ~1 ч) | JWKS с публичным ключом платформы (один на все сайты, `kid: platform-sso-1`) |
| `POST {CABINET_URL}/api/sso/token` | страница кабинета (same-origin, по сессионной куке) | `{ token, tenant, expiresIn }` — терминал этот эндпоинт НЕ зовёт |

## Токен (JWT RS256)

```json
// header
{ "alg": "RS256", "kid": "platform-sso-1", "typ": "JWT" }
// payload
{
  "iss": "platform-auth",
  "aud": "terminal",
  "sub": "<userId платформы, uuid>",
  "tenant": "<site-slug, ^[a-z0-9-]{2,32}$, напр. apex-ru>",
  "jti": "<uuid — одноразовый>",
  "iat": 1784980000,
  "exp": 1784980060
}
```

**Чеклист валидации на стороне терминала** (всё обязательно):
1. подпись по JWKS, принимать ТОЛЬКО `alg: RS256` (защита от alg-подмены);
2. `iss == "platform-auth"`, `aud == "terminal"`;
3. `exp` не истёк (TTL токена 60 с; допуск часов ±30 с);
4. `jti` не использовался ранее (one-shot; хранить видённые jti ≥ 2 мин);
5. `tenant` совпадает с `?site=` запроса — иначе 403 (ваша проверка подмены, решение A).

После успешной валидации: счёт ищется/создаётся по ключу `(tenant, sub)`; терминал чеканит свою сессию с TTL ≤ 15 минут.

**Необязательные claims** (demo-money / Р-446 / тариф 10.11):

- `account_kind`: `"demo" | "real"` — какой счёт открыть; нет — `demo`, незнакомое — 400.
- `leverage`: целое `1..=1000` — плечо счёта для **новых** позиций (итог портфеля /
  override клиента, посчитанный кабинетом на момент выпуска). Терминал записывает его
  в журнал счёта (`leverage_set`, оператор `cabinet-sso`), если оно отличается от
  текущего; открытые позиции держат своё плечо. Вне диапазона — 400 `invalid_leverage`;
  не удалось записать — 503 `leverage_sync_failed` (вход отклонён, fail-closed). Нет
  claim-а — плечо счёта не меняется (без назначения действует `PLATFORM_LEVERAGE`).
- `markup_bps`: целое `0..=500` — наценка на спред счёта в базисных пунктах (портфель
  Standard; решение владельца 10.11). Покупка исполняется дороже рынка на
  `price · bps / 10000`, продажа — дешевле, на открытии и закрытии.
- `commission_bps`: целое `0..=500` — комиссия за сделку в bps от нотионала (Pro /
  ENC Prime); списывается отдельной проводкой при каждом исполнении (открытие и
  закрытие, включая SL/TP, стоп-аут, отложенные ордера).

  Оба — тариф для **новых** позиций (итог портфеля / override клиента на момент
  выпуска), открытые закрываются по снимку тарифа при открытии. Терминал пишет
  `fees_set` в журнал счёта (оператор `cabinet-sso`), если тариф отличается от
  текущего. Пришёл один из двух — вторая ставка остаётся прежней. Вне диапазона —
  400 `invalid_fees`; не удалось записать — 503 `fees_sync_failed` (вход отклонён,
  fail-closed). Нет обоих — тариф не меняется (по умолчанию нули: без наценки и
  комиссии). Основной путь назначения — внутренний маршрут
  `POST /internal/sites/{tenant}/users/{sub}/{demo|real}/fees`; claims догоняют его
  при входе и продлении сессии.

## postMessage-протокол (iframe ↔ родитель-кабинет)

| Направление | Сообщение | Когда |
| --- | --- | --- |
| родитель → iframe | `{ "type": "sso.token", "token": "<jwt>" }` | при onLoad iframe и в ответ на refresh-запрос |
| iframe → родитель | `{ "type": "token.refresh.request" }` | когда сессии терминала осталось жить < 2 мин |
| родитель → iframe | `{ "type": "sso.logout" }` | сессия платформы погашена (ре-handoff невозможен) — терминал разлогинивается немедленно |

Обе стороны проверяют `event.origin` (родитель знает origin терминала, терминал получит список origin'ов кабинетов вместе с `frame-ancestors`).

**Гарантия единого логаута**: погашенная сессия кабинета не может переотдать токен ⇒ терминал разлогинивается не позднее своего TTL (≤ 15 мин); `sso.logout` делает это мгновенным, когда страница жива.

## Вход верхним уровнем (без iframe) — v1.1, 10.11.2026

Терминал работает и самостоятельной страницей (`terminal.<домен>`). iframe/postMessage
выше остаётся как есть; это второй путь к тому же `POST /v1/session`.

**1. Кабинет открывает терминал** (переход верхним уровнем, новая вкладка или та же):

```
https://terminal.<домен>/?site=<slug>#handoff=<jwt>&account=demo|real[&lang=ru|en]
```

- `handoff` — тот же JWT, что уходит в `sso.token` (TTL ≤ 120 с, одноразовость — на стороне кабинета);
- `account` — род счёта, на который вход (совпадает с claim `account_kind`); терминал
  запоминает его в `sessionStorage` (не секрет) для продления;
- `lang` — язык кабинета; терминал откроется на нём (иначе RU);
- токен **только во фрагменте**: фрагмент не уходит на сервер, в логи прокси и в `Referer`.
  Терминал стирает фрагмент сразу при загрузке (`history.replaceState`) и меняет токен на
  сессию (`POST /v1/session`). Токен в `sessionStorage`/`localStorage` не пишется.

**2. Продление без родителя.** За 2 минуты до истечения сессии терминал показывает
«Сессия закончится через N мин · Продлить», за 20 с — уходит сам (не чаще раза в минуту):

```
GET <кабинет>/api/sso/launch?account=demo|real&return=<адрес терминала без фрагмента>
```

От кабинета (маршрут делает команда кабинета):
- проверить свою сессию; нет — на свой логин, после логина — продолжить этот же launch;
- проверить `return` по **своему белому списку origin'ов терминала** (точное совпадение
  origin; иначе 400, никаких редиректов на чужие адреса);
- проверить, что `account` есть у пользователя (real — только если он открыт);
- выпустить handoff и ответить `302 Location: <return>#handoff=<jwt>&account=<…>[&lang=…]`;
- `Cache-Control: no-store`; JWT — тот же контракт, что выше.

Перезагрузка страницы терминала (токен жил только в памяти) идёт тем же путём.

**3. «В кабинет».** Кнопка ведёт на `<origin кабинета>/`. Origin берётся из
`cabinetOrigins` конфига терминала (`CABINET_ORIGIN`, можно несколько через пробел/запятую):
кандидат из фрагмента (`cabinet=`), `Referer` или `sessionStorage` принимается **только при
точном совпадении** с этим списком, иначе — первый из списка. Открытого редиректа нет.

**4. Выход.** «Выйти» → `POST /v1/session/logout` → `/logout` (страница терминала: «В кабинет»,
«Открыть терминал снова» = launch). Сессию кабинета выход из терминала не гасит.

Во фрейме кнопок «В кабинет»/«Выйти» и баннера сессии нет — их роль играет кабинет.
